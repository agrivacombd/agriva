# AGRIVA Supabase Send SMS Hook

This Edge Function replaces Supabase Auth's SMS transport with One9. It does **not** itself create a phone-password-reset flow; the application must separately invoke a supported Supabase phone OTP recovery flow and verify the OTP before changing a password.

## Required Edge Function secrets

Set these in Supabase Dashboard → Edge Functions → Secrets (never in source control):

- `SEND_SMS_HOOK_SECRET`: the complete value generated by Supabase Auth Hooks, including the `v1,whsec_` prefix.
- `ONE9_SMS_API_KEY`: the One9 API key.
- `ONE9_SENDER_ID`: optional; use `AGRIVA` only after One9 has approved the masking Sender ID. If omitted, the function currently requests `AGRIVA`; delivery can fail if it is not approved.

## Deploying safely

1. Deploy this function with JWT verification disabled **only after** confirming this handler's Standard Webhooks signature verification is present.
2. Copy the deployed function URL into Auth → Hooks → Send SMS → HTTPS.
3. Keep the generated hook secret private; save the hook.
4. Confirm phone auth is enabled and SMS auto-confirm is disabled in Supabase Auth settings.
5. Send a test OTP to a controlled, verified Bangladesh number and inspect provider delivery status.

Do not enable the Auth Hook until all three secrets exist and a successful test has been performed. A bad hook can interrupt phone OTP flows.

## One9 API

Uses `POST https://sms.one9.one/api/v3/sms/send` with Bearer authentication and JSON fields `recipient`, `sender_id`, `message`, and `type`. Check the One9 account's approved Sender ID and live pricing before production use.
